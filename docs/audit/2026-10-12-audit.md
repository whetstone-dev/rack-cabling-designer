# Compatibility audit, 2026-10-12

Environment: Windows 11 Pro, Node 24.13.0, Claude Code 2.1.216, Codex CLI 0.145.0. Cursor is installed (`~/.cursor` exists) but has no CLI on PATH. The skill is v0.1.0.

The audit separates three layers. **A layer is claimed only with the evidence listed for it.**

| Layer | Question it answers | Evidence |
|---|---|---|
| **Structural** | Are the files in the right place, in the right format, intact, with scripts and references? | `node tools/audit.ts`, which installs into a sandboxed home/project per platform and scope. Report: [2026-10-12-structural.md](2026-10-12-structural.md) |
| **Functional (local)** | Does the toolkit run *from the installed location* and give the expected results? | Same tool: `selftest`, `validate --strict` on the healthy examples, `validate` on the broken one (must fail), `build` (7 outputs), `--verify` |
| **Functional (real assistant, headless)** | Does the real assistant discover the skill, choose it on its own, and run it? | `tests/platform-smoke/smoke.ts`, which runs 4 cases with evidence taken from the CLI event stream |
| **Manual in the real assistant UI** | Does it work in the app people actually use (IDE, desktop)? | Not done by the auditor; checklist below |

The headless cases are:

- **control:** the skill is not installed, so it must not appear.
- **discovery:** the skill is listed.
- **implicit:** the task is given without naming the skill.
- **explicit:** the skill is invoked with `/` or `$`.

- Running the toolkit as the skill instructs printed `PASS: 0 error(s), 0 warning(s), 0 info · 1 rack(s), 8 device(s), 12 cable(s), 8 channel(s)`.
- Observation: live detection works, but not instantly. If the skill does not appear, wait a moment or run `/reload-skills`.

### Follow-up diagnosis (sub-agents, read-only)

**Codex:**
- The usage limit is still active until 2026-11-11.
- Error 1312 matches open bugs [openai/codex#30024](https://github.com/openai/codex/issues/30024), [#31768](https://github.com/openai/codex/issues/31768) and [#31220](https://github.com/openai/codex/issues/31220). The elevated Windows sandbox fails to start the Microsoft Store `pwsh` alias as its sandbox user. This is unrelated to the skill.
- Workarounds the user can choose: a standalone PowerShell first on PATH, `-c windows.sandbox=unelevated` for one run, or Codex ≥ 0.162 with the MXC sandbox.

**Cursor:**
- The editor is not installed. Only user data remains (logs show 2.4.37, then 2.5.17).
- Testing requires reinstalling it, plus optionally the `agent` CLI. The CLI has a headless `-p --output-format stream-json` mode and loads skills from `.cursor`, `.agents`, `.claude` and `.codex`.
- Per Cursor staff, the skill catalog is fixed when a chat starts, so test in a **new** chat. Duplicate copies may be listed twice.

## Defects found and fixed in this audit

| # | Defect | Fix |
|---|---|---|
| D1 | `--project` with a non-existent path created the whole folder tree and installed there, so a typo left stray folders | Project scope requires an existing folder (`validateProjectDir`) |
| D2 | `--project` pointing to a file failed late with a confusing rename error | Same check, with a clear message before anything is written |
| D3 | `--target` with a typo (e.g. `~/.typoapp/skills`) created folders in the home | The parent of the skills folder must exist; only the final folder is created |
| D4 | Ctrl+C during installation could stop between "backup" and "place" | SIGINT is deferred: the current destination finishes (or rolls back), the remaining ones are marked `cancelled`, and a second Ctrl+C aborts |
| D5 | Staging folders left by an aborted run accumulated in the state folder | Cleaned at the start of the next run, and the cleanup is logged |
| D6 | The smoke test could not tell "files copied" from "skill activated", and reported environment errors (account limits, sandbox) as skill failures | Rewritten with control, discovery, implicit and explicit cases, event-stream evidence and an `INCONCLUSIVE` status |
